\-------------------------------------------------------------------------------------------------------------

ระบบมาตรฐานสากลจะแบ่งการจัดการข้อมูลที่ไม่ต้องการใช้งานแล้วออกเป็น **3 ระดับหลัก คือ ระงับ (Suspend / Inactive), ยกเลิก (Void / Cancel) และ ลบ (Hard Delete)** เพื่อรักษาความถูกต้องของบัญชีและป้องกันไม่ให้ฐานข้อมูลเกิดข้อผิดพลาด

**1. การระงับ (Suspend / Inactive / Soft Delete)**

การระงับคือการ **เปลี่ยนสถานะข้อมูลให้หยุดทำงานชั่วคราวหรือถาวรโดยไม่ลบออกจากฐานข้อมูล** เพื่อเก็บประวัติอ้างอิงย้อนหลังไว้ทั้งหมด

- **ส่วนที่ทำหน้าที่ (กลุ่มข้อมูลเป้าหมาย):** ใช้กับข้อมูลพื้นฐาน (Master Data) และข้อมูลการตั้งค่าทั้งหมด ได้แก่ สินค้า (เช่น พัดลมที่เลิกขาย), ลูกค้า (เช่น นาย ก ที่เลิกทำธุรกิจหรือเสียชีวิต), พนักงานที่ลาออก, หมวดหมู่สินค้า, หน่วยนับ และประเภทต่าง ๆ
- **วิธีการทำงานของระบบ (เบื้องหลัง):** ระบบจะเปลี่ยนค่าในคอลัมน์สถานะจาก `Active` เป็น `Inactive` หรือบันทึกเวลาลงในช่อง `deleted_at` แทนการลบแถวข้อมูลทิ้ง
- **ผลลัพธ์ต่อหน้าจอและการใช้งาน:** ข้อมูลที่ถูกระงับจะหายไปจากหน้าจอเลือกใช้งานในปัจจุบัน (เช่น ตอนเปิดบิลใหม่จะค้นหาชื่อพัดลมหรือนาย ก ไม่เจอ) แต่เมื่อกดดูบิลเก่าหรือรายงานย้อนหลัง ข้อมูลทั้งหมดจะยังแสดงผลครบถ้วนสมบูรณ์

**2. การยกเลิก (Void / Cancel)**

การยกเลิกคือการ **ทำให้เอกสารธุรกรรมสิ้นผลบังคับใช้ทางการเงินและสต็อก** โดยยังคงเก็บหลักฐานการมีอยู่ของเอกสารนั้นไว้ในระบบ

- **ส่วนที่ทำหน้าที่ (กลุ่มข้อมูลเป้าหมาย):** ใช้กับเอกสารธุรกรรม (Transaction Data) ทั้งหมดที่มีเลขที่เอกสารกำกับ ได้แก่ บิลขาย, ใบเสร็จรับเงิน, ใบกำกับภาษี, ใบสั่งซื้อ, ใบเบิกสินค้า และรายการรับชำระเงิน
- **วิธีการทำงานของระบบ (เบื้องหลัง):** ระบบจะเปลี่ยนสถานะบิลเป็น `Void` หรือ `Cancelled` โดยห้ามลบเลขที่บิลทิ้งเพื่อไม่ให้เลขที่เอกสารรันข้ามหรือแหว่ง พร้อมทั้งสร้างรายการปรับปรุงย้อนกลับ (เช่น คืนสต็อกสินค้ากลับเข้าคลังอัตโนมัติ) และบันทึกชื่อผู้ยกเลิกกับเหตุผลไว้ในประวัติ (Audit Log)
- **ผลลัพธ์ต่อหน้าจอและการใช้งาน:** บิลที่ถูกยกเลิกจะยังคงปรากฏอยู่ในหน้ารายการบิลพร้อมแถบคาดหรือป้ายกำกับว่า "ยกเลิก" แต่ยอดเงินของบิลนั้นจะถูกตัดออกจากการคำนวณยอดขายและรายงานทางบัญชีทั้งหมด (หากเป็นบิลที่ออกใบกำกับภาษีไปแล้ว ระบบจะบังคับให้ออก "ใบลดหนี้" แทนการกดยกเลิกตรง ๆ)

**3. การลบ (Hard Delete)**

การลบคือการ **ทำลายข้อมูลออกจากฐานข้อมูลอย่างถาวร** จนไม่สามารถกู้คืนกลับมาได้อีก

- **ส่วนที่ทำหน้าที่ (กลุ่มข้อมูลเป้าหมาย):** ใช้ได้เฉพาะกับข้อมูลทุกประเภทที่ **"ยังไม่เคยถูกนำไปใช้งานหรืออ้างอิงในระบบเลย"** เท่านั้น เช่น สินค้าที่เพิ่งสร้างผิด, หมวดหมู่ที่ตั้งชื่อซ้ำและยังไม่มีสินค้าผูกอยู่, หรือบิลฉบับร่าง (Draft) ที่ยังไม่ได้กดยืนยันและยังไม่ออกเลขที่เอกสาร
- **วิธีการทำงานของระบบ (เบื้องหลัง):** ระบบจะทำการตรวจสอบความเชื่อมโยง (Dependency Check) ก่อนเสมอ หากพบว่าไม่มีบิลหรือข้อมูลอื่นผูกอยู่ ระบบจะใช้คำสั่งลบแถวข้อมูลนั้นออกจากตารางในฐานข้อมูลทันที
- **ผลลัพธ์ต่อหน้าจอและการใช้งาน:** ข้อมูลจะหายไปจากระบบอย่างสมบูรณ์ทั้งในหน้าปัจจุบันและรายงานย้อนหลัง หากข้อมูลนั้นเคยถูกใช้งานไปแล้วแม้แต่ครั้งเดียว ระบบมาตรฐานจะบล็อกปุ่มลบถาวร และบังคับให้ผู้ใช้เปลี่ยนไปใช้วิธี **"ระงับ"** หรือ **"ยกเลิก"** แทน

**ตารางสรุปเปรียบเทียบการทำงานทั้ง 3 รูปแบบ**

| **หัวข้อเปรียบเทียบ**    | **ระงับ (Suspend / Inactive)**                | **ยกเลิก (Void / Cancel)**                | **ลบ (Hard Delete)**                      |
| ------------------------ | --------------------------------------------- | ----------------------------------------- | ----------------------------------------- |
| **ข้อมูลที่ใช้**         | สินค้า, ลูกค้า, พนักงาน, หมวดหมู่, หน่วยนับ   | บิลขาย, ใบเสร็จ, เอกสารทางบัญชีและสต็อก   | ข้อมูลที่สร้างผิดและยังไม่เคยถูกใช้งานเลย |
| **สถานะในฐานข้อมูล**     | ข้อมูลยังอยู่ครบ แค่เปลี่ยนสถานะเป็นปิดใช้งาน | ข้อมูลยังอยู่ครบ แค่เปลี่ยนสถานะเป็นโมฆะ  | ถูกลบหายไปจากฐานข้อมูลถาวร                |
| **ผลต่อประวัติย้อนหลัง** | บิลเก่าและรายงานเก่ายังแสดงข้อมูลเดิมครบ      | ยังเห็นประวัติบิล แต่ไม่นำยอดเงินมาคิดรวม | ไม่มีประวัติหลงเหลืออยู่ในระบบ            |

นี่คือรายละเอียดของ **ข้อความแจ้งเตือนบนหน้าจอ (Alert Message)**, **ผังการทำงาน (Flowchart)** และ **ตารางสิทธิ์การเข้าถึง (Permission Matrix)** ตามมาตรฐานสากล เพื่อให้คุณนำไปใช้ประกอบการออกแบบระบบหรือส่งต่อให้ทีมพัฒนาได้ทันทีครับ

**1. ข้อความแจ้งเตือนบนหน้าจอ (Alert Message)**

ข้อความแจ้งเตือนที่ดีต้องระบุ **"ผลกระทบที่จะเกิดขึ้น"** ให้ชัดเจน เพื่อป้องกันไม่ให้ผู้ใช้งานกดผิดพลาด

**กรณีที่ 1: กดปุ่ม "ระงับ" (Suspend / Inactive)**

- **หัวข้อแจ้งเตือน:** ยืนยันการระงับการใช้งานข้อมูล
- **รายละเอียดข้อความ:** "คุณต้องการระงับการใช้งาน [ชื่อสินค้า/ลูกค้า/หมวดหมู่] ใช่หรือไม่? หากระงับแล้ว รายการนี้จะไม่แสดงให้เลือกในบิลใหม่ แต่ข้อมูลในบิลเก่าและรายงานย้อนหลังจะยังคงอยู่ครบถ้วน (สามารถกดเปิดใช้งานใหม่ได้ภายหลัง)"
- **ปุ่มกด:** `[ ยืนยันการระงับ ]` (สีส้ม/เหลือง) และ `[ ปิดหน้าต่าง ]`

**กรณีที่ 2: กดปุ่ม "ยกเลิก" (Void / Cancel)**

- **หัวข้อแจ้งเตือน:** ยืนยันยกเลิกบิล [เลขที่บิล]
- **รายละเอียดข้อความ:** "การยกเลิกบิลจะทำให้เอกสารนี้เป็นโมฆะ ยอดเงินจะถูกตัดออกจากรายงาน และระบบจะคืนสต็อกสินค้ากลับเข้าคลังอัตโนมัติ (ไม่สามารถกู้คืนบิลนี้ได้อีก)"
- **ช่องบังคับกรอก:** กล่องข้อความ *"กรุณาระบุเหตุผลในการยกเลิก (บังคับกรอก)"*
- **ปุ่มกด:** `[ ยืนยัน ]` (สีแดง) และ `[ ปิดหน้าต่าง ]`

**กรณีที่ 3: กดปุ่ม "ลบ" (Hard Delete)**

แบ่งเป็น 2 สถานการณ์ตามเงื่อนไขของระบบ:

- **3.1 เมื่อข้อมูลยังไม่เคยถูกใช้งาน (ลบได้):**
  - **หัวข้อ:** ยืนยันการลบข้อมูลถาวร
  - **ข้อความ:** "คุณต้องการลบ [ชื่อรายการ] ออกจากระบบอย่างถาวรใช่หรือไม่? ข้อมูลนี้จะถูกลบหายไปและไม่สามารถกู้คืนได้อีก"
  - **ปุ่มกด:** `[ ลบถาวร ]` (สีแดง) และ `[ ยกเลิก ]`
- **3.2 เมื่อข้อมูลเคยถูกใช้งานในบิลแล้ว (ระบบบล็อกการลบ):**
  - **หัวข้อ:** ไม่สามารถลบข้อมูลนี้ได้
  - **ข้อความ:** "ไม่สามารถลบ [ชื่อรายการ] ได้ เนื่องจากมีประวัติการใช้งานในระบบแล้ว (พบในเอกสารจำนวน X รายการ) กรุณาใช้ปุ่ม 'ระงับการใช้งาน' แทน เพื่อป้องกันข้อมูลในบิลเก่าเสียหาย"
  - **ปุ่มกด:** `[ เปลี่ยนเป็นระงับการใช้งาน ]` และ `[ รับทราบ ]`

**2. ผังการทำงานของระบบ (System Flowchart)**

ลำดับการตัดสินใจของระบบเบื้องหลังเมื่อผู้ใช้กดปุ่มจัดการข้อมูลที่ไม่ต้องการแล้ว

**text**
```
[ ผู้ใช้กดปุ่ม "ลบ / ยกเลิก" รายการ ]
                 │
                 ▼
  < เป็นเอกสารธุรกรรม (บิล) หรือไม่? >
         ├── ใช่ ──► [ ตรวจสอบสถานะเอกสาร ]
         │               ├── ยังเป็นฉบับร่าง (Draft) ──► ( ลบถาวรได้ทันที )
         │               └── ยืนยัน/ออกเลขบิลแล้ว ──► ( บังคับใช้ "ยกเลิก / Void" + คืนสต็อก + เก็บ Log )
         │
         └── ไม่ใช่ (เป็นสินค้า, ลูกค้า, หมวดหมู่, หน่วยนับ)
                 │
                 ▼
  < เคยถูกนำไปอ้างอิงในบิลหรือสินค้าอื่นหรือไม่? >
         ├── ไม่เคยเลย ──► [ แสดงหน้าต่างยืนยัน ] ──► ( ลบถาวร / Hard Delete )
         │
         └── เคยใช้งานแล้ว ──► [ บล็อกการลบถาวร ] ──► ( บังคับเปลี่ยนเป็น "ระงับ / Inactive" )

```

ใช้โค้ดอย่างระมัดระวัง

**3. เงื่อนไขการตรวจสอบสิทธิ์ (Role & Permission Matrix)**

ระบบมาตรฐานจะไม่ให้พนักงานทุกคนมีสิทธิ์กดยกเลิกหรือลบข้อมูลได้ทั้งหมด เพื่อป้องกันการทุจริตและข้อผิดพลาด

| **ระดับผู้ใช้งาน (Role)**               | **ระงับ (Inactive)** | **ยกเลิกบิล (Void)** | **ลบถาวร (Hard Delete)** | **เงื่อนไขเพิ่มเติม**                                                               |
| --------------------------------------- | -------------------- | -------------------- | ------------------------ | ----------------------------------------------------------------------------------- |
| **พนักงานขาย / แคชเชียร์ (Staff)**      | ❌ ไม่อนุญาต          | ⚠️ เฉพาะบิลตัวเอง    | ❌ ไม่อนุญาต              | ยกเลิกได้เฉพาะบิลที่เพิ่งเปิดในวันเดียวกันและยังไม่ปิดกะ หากข้ามวันต้องให้หัวหน้ากด |
| **หัวหน้างาน / ผู้จัดการ (Manager)**    | ✅ อนุญาต             | ✅ อนุญาต             | ⚠️ เฉพาะฉบับร่าง         | สามารถอนุมัติยกเลิกบิลข้ามวันได้ และระบบจะบันทึกชื่อผู้อนุมัติไว้ในประวัติเสมอ      |
| **ผู้ดูแลระบบ / เจ้าของกิจการ (Admin)** | ✅ อนุญาต             | ✅ อนุญาต             | ✅ อนุญาต                 | ลบถาวรได้เฉพาะข้อมูลที่ยังไม่เคยถูกใช้งานจริงเท่านั้น (ตามกฎของฐานข้อมูล)           |
